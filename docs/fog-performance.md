# Оптимизация тумана 0.8.6

## Расчёт

Раньше 3D-туман выполнял до 16/32/48/64 шагов в каждом пикселе основного framebuffer. Каждый шаг вычисляет два масштаба процедурного 3D-шума, высотную плотность, пропускание и при включённых лучах читает карту солнечных теней.

Теперь параметр `fogResolution` выбирает 50, 75 или 100 процентов по каждой стороне. По умолчанию используется 50%, включая старые конфиги без нового поля. В 1920×1080 основной объёмный проход поэтому обрабатывает 960×540, то есть вчетверо меньше пикселей; это не обещание четырёхкратного роста общего FPS. Плотность, дальность и выбранное количество шагов не уменьшены.

Промежуточный RGBA16F-буфер хранит пропускание, интегрированный вес солнечного света и расстояние до конца луча. Полноразмерный проход смешивает четыре соседних результата с весами по расстоянию. Фазовая функция и солнечный ореол вычисляются по точному направлению текущего пикселя. Глубина мира читается через depth-only view и `texelFetch`, без размытия.

Соседи с несовпадающим расстоянием отбрасываются. Когда подходящих соседей нет, текущий пиксель интегрируется отдельно до собственной поверхности за четыре шага. Ограничение стоимости этого редкого случая существенно: длинный цикл лишь в нескольких дорожках GPU может замедлить всю группу пикселей. На тонких далёких объектах точность интегрирования может быть ниже, чем в режиме 100%; длинный луч никогда не переносится с фона на ближний объект.

Обычный высотный туман и диагностические режимы используют прежний полноразмерный проход без промежуточного буфера. При нулевой неоднородности и выключенных солнечных лучах применяется аналитический интеграл вместо ray marching. Ночью не выполняются бесполезные выборки солнечной карты. При смене разрешения/размера окна буферы пересоздаются после ожидания GPU; обёртки основного framebuffer освобождаются без удаления заимствованной текстуры Minecraft.

## Проверки

```powershell
.\gradlew.bat build
.\gradlew.bat verifyFogCaptures
.\gradlew.bat verifyFogPerformance -PfogPerformanceCheck
```

`build` компилирует прямой, уменьшенный и восстанавливающий варианты GLSL тем же shaderc, что использует VulkanMod. Проверяются миграция `fogResolution`, пределы, сохранение и сброс к 50%.

`verifyFogCaptures` проверяет настоящий туман обоих типов, чтение глубины, покрытие экрана, закрытие близкой стеной и выключение эффекта под водой.

`verifyFogPerformance` запускает отдельный клиент в 1920×1080 без VSync и ограничения FPS. Камера и время суток фиксируются, движение сгустков отключается. После прогрева сравниваются 100/50/75/100/50%, затем 100/50% с солнечными тенями. Для каждого режима отбрасываются две секунды прогрева и собираются четыре секунды измерений. Записываются интервалы целого кадра и неблокирующие Vulkan timestamps собственно прохода тумана. Профилирование находится только в validation-моде и в распространяемый JAR не входит.

Результаты сохраняются в `run-fog-check/fog-performance.csv`, кадры — в `run-fog-check/screenshots/perf-*.png`. Изображения 50/75% сравниваются с полноразмерными в области ландшафта; допустимая средняя ошибка RGB — 2/255, доля каналов с ошибкой больше 8 — до 2%. Скорость выводится отдельно от проверок изображения: общий FPS зависит также от оконного режима, другой нагрузки GPU, частот и остальных проходов Minecraft.

## Измерено 31 октября 2026

Minecraft 26.1.2, VulkanMod 0.6.8, 1920×1080, 32 шага, стандартная плотность и дальность. Медианы GPU timestamps включают интегрирование, восстановление и переходы ресурсов тумана:

| Режим | 100% | 50% | Ускорение прохода |
| --- | ---: | ---: | ---: |
| 3D-туман без солнечной карты, среднее двух медиан | 1,427 мс | 0,643 мс | 2,22× |
| 3D-туман с солнечными лучами | 1,845 мс | 0,722 мс | 2,55× |

Для 75% без солнечной карты получено 1,088 мс. Медианное время целого кадра в парных сериях без солнечной карты — в среднем 1,702 мс при 100% и 0,792 мс при 50%; с солнечной картой — 2,580 и 1,462 мс. Это отдельная тестовая сцена, а не обещание такого же FPS в любом мире.

Средняя ошибка RGB для двух сравнений 50% — 0,351 и 0,273/255; для 75% — 0,368/255; для 50% с солнечной картой — 0,344/255. Все проверки изображения пройдены. Эти числа включают небольшие изменения живых сущностей между кадрами.
